## What to build

**Throwaway prototype. Produces a decision, not shippable code.**

Code the model writes inside a generated tree is replaced by a placeholder before storage, and the live function lives
only in a process-local registry that is cleared immediately after execution. So the corpus cannot record what the model
actually wrote, versions cannot be compared, and a harvested pattern ships with its logic missing — while the corpus
instructs the model to ADOPT it.

Establish whether the emitted form can reach the emit primitive as something other than an already-compiled interpreter
closure. Try, in order: the model passing a quoted form; interpreter source metadata available at registration; and only
then the fallback of authoring code nodes as strings by convention.

**This can falsify a ratified decision.** If only the fallback works, it changes the DSL surface the model is taught,
which requires re-grilling rather than an in-flight decision — stop and report.

## Disciplines (verbatim — do not summarise, do not skip)

- **Never assume. Chase every bug to its ROOT CAUSE.** No band-aids, no "probably," no jumping to conclusions.
  Reproduce -> minimize -> fix the actual cause. Don't blame the network or the model — the cause is in the code or
  the setup. And rule out the *harness itself* (a stuck flag, a stale fixture, a tool that stores results oddly can
  fake a symptom): distinguish "the work is wrong" from "my measurement is wrong."
- **TDD for real logic: red -> green -> refactor, one test at a time.** Vertical tracer-bullet slices, never
  horizontal (don't write all tests then all code). Test **behavior through public interfaces**, so tests survive
  refactors.
- **Injected-capability seam pattern.** Keep logic pure and testable; inject effects (clock, RNG, network, storage)
  as capabilities that **default to the real impl and are faked in tests**.
- **Durable tests AND live QA.** A passing unit test is necessary, not sufficient — also drive the real thing. Then
  turn what you verified into a durable test so it's guarded on every run.
- **Dispatch sub-work to fresh agents, then INDEPENDENTLY and ADVERSARIALLY verify it.** Never trust a subagent's
  "done / all green" report — re-run the proof, re-read the code, try to break the claims, demand proof.
- **Report faithfully** — including your own mis-steps and anything you couldn't verify.

- **Never weaken a generated test to make it pass.** A `/propagate`-generated test is contract. If it is wrong, the
  spec is wrong: report it, the orchestrator `/tend`s and re-propagates.
