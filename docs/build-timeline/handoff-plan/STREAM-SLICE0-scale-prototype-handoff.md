## The premise to prove (all four, with hard numbers)
The pipeline OOMs because every stage does `(vals (rmp/project :ontology/concepts))` — materializing the whole concept + embedding map. The plan's fix is to reduce directly over the streaming `es/read`. PROVE:

1. **`reduce-concepts` is BOUNDED and BYTE-IDENTICAL to project.** A hand-rolled fold of the REGISTERED `:ontology/concepts` reducer over a tag-scoped, windowed `es/read` stream produces state EQUAL to `(rmp/project ctx :ontology/concepts)` (for the ontology's tag scope), and its peak heap is bounded to the metadata working set (not a second full copy).
2. **`(vals (rmp/project …))` is the OOM.** Under a constrained `-Xmx`, the current full-materialization path spikes / OOMs at scale where `reduce-concepts` does not.
3. **`reduce-concept-embeddings` holds ONE vector at a time.** Streaming `:ontology/concept-embedded` events one-at-a-time (each carries one vector) to build only a small per-URI FLAG set runs in bounded heap, vs `get-all-concept-embeddings` (`read_models.clj:2111-2128`) which realizes the whole vector map.
4. **(If tractable) ColBERT disk retrieval is bounded** vs the in-memory cosine scan (`retrieval.clj:719-728`). Lower priority — do 1-3 first; note 4 if time permits.

## What to build (a throwaway script, e.g. `development/src/stream_slice0_prototype.clj`)
1. **Generate a large ontology in a temp event store.** ~50k concepts (and a subset with embeddings). Use the eb12 harness ctx (`eb12-graph-b-central-evolver` `make-ctx {:store :sqlite}` — the persistent off-heap log; access the private fn via `(deref #'…/make-ctx)` as the mt7* verify scripts do). Emit `:ontology/concept-created` events for a single `ontology-id` — via the `create-concept` command (`ai.obney.orc.ontology.core.commands`, through the command processor the pipeline uses — see `deterministic_skeleton.clj:120-129` `cp/process-command` for the inline pattern) OR direct event append if faster. Give each a uri/label/type + a modest `:attributes`. Embed a subset via the `embed-concept` command or a direct `:ontology/concept-embedded` event with a real-length vector (match the model dim; see `read_models.clj:2024-2052`). Keep the generator itself bounded (emit in batches; don't hold 50k in memory to create them).
2. **Hand-roll `reduce-concepts`** (the Slice-1 primitive, prototype-local): fold the registered concepts reducer over `es/read` windows. Mechanics:
   - the reducer + event types: `ai.obney.orc.ontology.core.read-models` exposes `concept-events` (the `:types`) and the `concepts*` reducer multimethod (fold it: `(reduce concepts* {} window-events)`). VERIFY these are the right/public names; if the registered reducer must be fetched from the read-model registry (`rmp`), use that instead — do NOT fork a second notion of concept state (discipline 8).
   - the stream: `ai.obney.grain.event-store-v3.interface` `es/read` (already used at `deterministic_skeleton.clj:287`) returns an `IReduceInit`; query `{:tenant-id … :tags #{[:ontology ontology-id]} :types concept-events :after <cursor> :limit <window>}`. Page by advancing `:after` past the last event id until a window returns `< limit` (exhausted) — copy the offset/exhausted loop from `apply-aggregation-transform!` (`rlm_discovery.clj:1331-1398`).
   - fold each window's events into a per-URI state accumulator, then `(reduce rf init (vals state))`.
3. **Hand-roll `reduce-concept-embeddings`:** stream `:ontology/concept-embedded` events one-at-a-time; `rf` keeps only a per-URI flag/count, DISCARDS the vector.
4. **Measure.** Run under a CONSTRAINED heap (`-J-Xmx` low enough that full materialization is stressed — start ~512m–1g and tune). Report, for each of (a) `(vals (rmp/project :ontology/concepts))`, (b) `reduce-concepts`, (c) `get-all-concept-embeddings` vs (d) `reduce-concept-embeddings`: peak heap (via `(-> (Runtime/getRuntime) …)` sampling around the call, or a coarse before/after + GC), whether it completed or OOM'd, and wall time. AND assert `reduce-concepts` state `=` `(rmp/project …)` state (byte-identical, on the same tag scope).
