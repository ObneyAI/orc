# Identity scope in coordinated work

Use distinct meanings for original source/root, parent coordination, expected child owner and fresh child invocation. When the host supplies its own IDs, declare whether a packet belongs to the coordinator or a child; an inactive child invocation can be explicitly null. Native ORC execution provenance may supply the needed binding instead—do not add redundant IDs without a consumer need.

Bind actual returned work to its current source, role and expected child. Validate that join before semantic routing or merging. Return a consultation answer to the requesting child, then issue or resolve the fresh revisit identity. Change only the requesting owner's expected reference; retain unaffected sibling work and stable effect identities. Give downstream models accurate described ownership, rather than asking them to infer equivalence between differently scoped UUIDs.
