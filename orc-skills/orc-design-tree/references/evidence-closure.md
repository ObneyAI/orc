# Complete the investigation before claiming the goal

Use this when an authored agent can consult tools or specialists and decide whether the task is complete. A truthful summary of the currently visible evidence can still stop too early: an answerable material question may remain open.

## Distinguish evidence states

Represent not-yet-requested, retrieved, observed-unavailable, superseded and irrelevant-to-this-goal separately where they affect decisions. An empty field only says the value is absent from this packet. It does not prove the world lacks the evidence, that the tool cannot obtain it, or that another specialist already checked it.

Give the completion checker the original goal, current artifacts, material qualifications, and relevant evidence-access options. The routing model also needs these facts. Putting a tool catalog only on the router leaves a preceding critic unable to tell whether a gap is answerable. A router can then accept an authoritative-sounding but underinformed critique.

A useful evidence question records its obligation, why the answer matters, who owns it, the available described resolver, observation state, and the actual answer or blocker. Keep this focused: unrelated tools and the entire execution history do not belong in every model call. The source inventory describes what can be inspected; it does not reveal or invent unread contents.

## Close questions semantically

Ask whether a remaining question could change the requested conclusion or action. Consult a suitable available source when it could. Re-enter the original owner with the answer, relevant prior artifact and current feedback, then reassess the parent goal. Ownership transfer is a different action and needs its own explicit contract.

Do not require every tool to run. A current authoritative prohibition can make an older optional exception irrelevant. A fully supported negative recommendation can satisfy decision support. Conversely, calling an unresolved task complete merely because the wording says “on current evidence” changes the goal without permission. Preserve an explicit wait or handoff when a material question really cannot be answered.

## Prove both stopping and continuation

Use one deficient artifact with an answerable material gap, and one correct qualified artifact that should be accepted. Verify actual resolver invocation, answer transfer, original-owner resumption and retained independent work. Inspect exact model inputs, not only declared reads. Check that the same completion contract permits the valid negative outcome without demanding irrelevant work.

A model critic is evidence, not an oracle. A finite decision model can select the next route; generated feedback helps when revision needs more than a choice. Neither a schema-valid result nor a critic's PASS establishes that all material questions were answered.
