# Structured validity and source fidelity

Use this when a model change yields valid but surprising records, optional fields, generated specialist output or a source-supported conclusion. These are evidence boundaries, not model rankings or a new per-model parsing recipe.

## Locate the first divergence

Compare the original typed value and described contract, the actual model-visible input view, the adapter's serialized request, the raw response, the unchanged paired decoder and canonical writes. Keep the actual node start, item context and physical attempt attached. A prime preview and a specialist's full packet are different input scopes. Count each authored description within its actual field or inherited output scope; finding its words elsewhere in a prompt does not prove that field retained its meaning.

A strict schema defines allowed shape; actual remote enforcement depends on the endpoint, and the paired decoder must still validate the response. It cannot require the correct source record, source order, interpretation, relationship or optional state when multiple states are permitted. For an optional nullable comment, absent, present-null and present-text are three valid states. If the source contains explicit null and the raw answer chooses the absent branch, the decoder can faithfully produce an incorrect source copy. That is distinct from the input encoder dropping null or the decoder changing a present branch to absence. Preserve the original failure before changing anything.

On the inspected strict codec, optional nullable output entries use an explicit presence branch; the input view preserves native omission and bare null. Input/output aliases for typed fixed keys can also differ. These representations preserve identity but are not textually symmetric. Use the schema-derived input plan and paired output decoder; do not strip wrappers, infer native key types from their spelling, stringify nested objects or add model-specific cleanup. An alternative input presentation remains an experimental hypothesis until a controlled fixed-leaf comparison demonstrates value and compatibility.

## Choose the right next action

- If the serialized request omitted a declared value, description or supported option, repair that boundary and retain a public regression witness. A prompt patch is not evidence that the boundary was fixed.
- If raw output violates the actual wire schema, inspect endpoint admission, effective output mode, finish reason and completion headroom before changing the authored contract. Retain incomplete responses; raising allowance is a recorded configuration change, not a parsing repair.
- If raw output is valid but contradicts supplied records, keep the source contract. For exact copies, code can check complete native record equality, unique source IDs, original order and presence. Semantic support needs an appropriate assessment. Feed a concrete discrepancy to the actual owner for a bounded revision rather than editing its answer.
- If a model is refused before generation, report admission or capacity separately from content quality. Preserve privacy/capability policy. A paid sibling or fallback response does not establish that the original endpoint worked.

A schema-valid generated `code` string does not prove correct ORC API or tool use. Inspect the executed program, available symbols, tool argument/result contracts and actual feedback. Undefined functions, undeclared writes or an invalid emitted node are execution/API failures; keep them separate from a correctly executed operation whose valid answer misinterprets source content. Diagnose missing or contradictory API guidance before attributing those failures to model capability.

A mandatory record check and a semantic judge are complementary. A successful first answer does not exercise correction, and a judge's agreement does not prove correctness. See [judge calibration](../../orc-judges/references/rubrics-and-calibration.md) before using those assessments for GEPA.

## Preserve comparison scope

Hold task, native sources, contracts, instructions and decoding constant when comparing model configuration. Prove the actual request difference rather than trusting a DSL diff. A verified request differing only at model still does not hold remote provider defaults, reasoning or routing constant. For meaning experiments, compare the fixed extractor separately from the adaptive trajectory: changed iteration limits, provider, generated code or completion allowance prevent a whole-trajectory description-only claim. Keep failed comparators and unavailable cells in the ledger.

Controlled inline/emitted researcher fixtures establish those constrained interfaces. They do not prove autonomous architecture choice, general-agent completion or broad superiority over an ordinary loop. Test integrated authored behaviors and fresh-agent construction separately.
