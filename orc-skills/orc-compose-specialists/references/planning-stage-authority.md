# Planning-stage authority before effects

Use this when a specialist both interprets intent and attempts to apply it. A valid typed proposal or booking recommendation may identify what should happen before current terms or other application authority exist.

Preserve the typed recommendation. Return a separate owned planning status for wholly absent authority before any proposal, approval, intent or external effect is applied. Let the semantic controller choose consultation; return the exact answer to a fresh invocation of the original specialist. Carry the original obligation and previously issued proposal through that seam. The initial valid recommendation is not a malformed provider response.

Keep effect guards authoritative. A partial or mismatched returned consultation is different from absent planning authority and remains a refusal. Consultation also does not authorize substituting changed terms into an already approved payload. At send time, use the exact approved identity/payload and observe the actual callee result.

## Evidence and limits

The first six-turn live conversation in preserved first-pilot outcomes (historical local experiment; private archive not bundled) used 31 physical Luna calls and 107 generated fields, with five answered turns and one execution failure. Its transport was faithful. The initial scheduling delegate accepted a valid typed booking intent for the approved proposal but threw for absent consultation before its parent could request terms. The guard prevented effects. That run did not reach the price-change hook and did not prove stale-price refusal.

The separate v4 report (historical local experiment; private archive not bundled) and complete consumer action diff (historical local experiment; private archive not bundled) record the narrow planning precondition. It applies only to propose/book for an observed slot when both terms and requester are absent. It retains the entire typed analysis unchanged; partial or mismatched returned authority still reaches the existing refusal.

Root independently reran the focused proof: one test, 44 assertions, using actual ORC/SIO, Grain commands/events/projections, SQLite/LMDB and a separate peer process; final model HTTP was controlled. Both immediate propose and book recommendations reached the semantic controller as needs-terms before effects, then returned through consultation to fresh specialist invocations. The booking sent the original approved price/version once after the peer price changed; the peer refused and no booking was created. Three partial/mismatched-authority controls were narrower direct code-seam checks.

The v4 report declares **4 obligations, 4 covered in declared scope**, including that narrower control obligation. This is deterministic consumer-workflow evidence, not live v4 model acceptance, a new ORC parser/runtime fix, general distributed authority or crash recovery. A live v4 result must be evaluated separately.
